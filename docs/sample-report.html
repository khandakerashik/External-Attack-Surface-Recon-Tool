Methodology, confidence & limitations

Workflow

  1. Passive discovery - subfinder, amass (passive), assetfinder/findomain (if installed), Certificate Transparency (crt.sh, Cert Spotter), web-archive hostnames.
  2. Resolution & enrichment - dnsx, Team Cymru ASN data, CDN identification, Shodan InternetDB (passive ports/CPEs/CVEs, CDN IPs skipped).
  3. DNS & e-mail posture - SPF, DMARC, DKIM (common selectors), MTA-STS, TLS-RPT, DNSSEC, CAA, wildcard detection.
  4. Historical URLs - gau / waybackurls classification (secrets in URLs, sensitive files, API docs, admin paths).
  5. Authorised active checks (only after explicit scope review and confirmation) - rate-limited port scan (naabu/nmap), service fingerprinting (nmap -sV), HTTP probing and a low-rate web asset inventory of the approved hosts (httpx), TLS posture, optional crawling (katana), non-intrusive nuclei templates (dos/fuzz/intrusive/brute-force/default-login tags excluded, no out-of-band interactions), AXFR test for in-scope roots.
  6. Correlation - versions mapped to NVD CPEs with local range matching, enriched with CISA KEV and FIRST EPSS.

Confidence levels

  • confirmed directly observed (e.g. open port, expired certificate, AXFR response).
  • firm matched by a specific detection (nuclei template, takeover fingerprint).
  • potential inferred from version banners or third-party passive data; requires validation.
  • tentative heuristic signal (e.g. back-ported package, login page by title).

Limitations

  • Passive sources are incomplete and can be stale; some sources need API keys (configure subfinder provider-config).
  • Version-based CVE mapping cannot see vendor back-ports, compensating controls or non-default configurations.
  • Hosts behind CDNs/WAFs receive reduced port coverage by design. Shared hosting IPs may carry data unrelated to the target.
  • Absence of a finding is not evidence of absence of vulnerability; this is not a substitute for a full penetration test.
